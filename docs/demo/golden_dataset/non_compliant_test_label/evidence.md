# Golden case: NON_COMPLIANT (controlled test label)

## What this is

A synthetic, clearly-marked **TEST/DEMO label** (`label.png`), not a real
commercial product. Per the task that produced this dataset, a real product
must never be misrepresented as non-compliant — so this case uses a
constructed label instead, exactly as that task's own Part 3 permits.

The label is clean, printed, single-column text so OCR/extraction confidence
stays high — the verdict below comes from a genuine rule violation, not from
noisy input. The image (`label.png`) is generated by `generate_label.py` in
this same directory — run it to regenerate the exact same artifact.

## The single deliberate violation

The label states:

```
MRP Rs. 45.00
```

with no statement that this is inclusive of all taxes. Rule 6(1)(e) of the
Legal Metrology (Packaged Commodities) Rules, 2011 requires the Maximum Retail
Price declaration to state it is inclusive of all taxes. Every other field on
the label is filled in correctly and completely, so the demo isolates exactly
one violation against six otherwise-clean fields.

## Actual pipeline run

Executed against the real, running PraMaan API (`POST /api/scans`, citizen_demo
account) — see `actual_api_response.json` for the full, unedited response.

| Field | Status | Reason |
|---|---|---|
| manufacturer_packer_importer | PASS | Name and address declared |
| country_of_origin | NOT_APPLICABLE | Not an imported product |
| common_generic_name | PASS | Declared |
| net_quantity | PASS | `125 g` — recognised unit |
| date_of_manufacture | PASS | Declared |
| **retail_sale_price** | **FAIL** | `Rs. 45.00` does not state inclusive of all taxes (Rule 6(1)(e)) |
| consumer_care_details | PASS | Declared |

**Overall verdict: NON_COMPLIANT** — the aggregation rule
(`aggregate_verdict_from_statuses` in `app/pipeline/rule_engine.py`) returns
NON_COMPLIANT whenever any applicable field FAILs, regardless of how many
fields PASS. That is exactly what happened here: one genuine FAIL, six PASS/
NOT_APPLICABLE, verdict NON_COMPLIANT.

## Reproducibility

`replay.json` shows a live `/api/scans/{id}/replay` call: replaying this scan
against the currently-loaded rule pack reproduces the identical verdict and
per-field statuses (`"reproduced": true`), and records the exact rule-pack
SHA-256 hash the scan was evaluated against.

## Why this is not "gaming" the demo

- The violation (missing "inclusive of all taxes") is one of the most common
  real-world Legal Metrology violations in India — this is not an invented or
  hypothetical rule.
- No code path treats this image, its filename, or its content specially. The
  same `evaluate_field` / `_evaluate_retail_sale_price` functions that decided
  this run also decided all 11 real-world REVIEW verdicts and the two existing
  `test_pipeline_e2e.py` fixture tests.
- The label is explicitly marked as a test artifact in two places (a red
  banner across the top and a footer line) so it can never be mistaken for a
  real product being called non-compliant.
